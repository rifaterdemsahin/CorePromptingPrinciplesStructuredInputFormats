🏛️ How LLM Contexts Process Structured Data

Context Anatomy

An LLM context window is a unified sequence of tokens containing instructions, roles, background documents, dynamic user inputs, and few-shot examples. Structure prevents attention dilution and ambiguity.

1. System Prompt
Markdown Roles (`### ROLE`), Output Rules, Schema constraints
→
2. Input Data Enclosure
XML (`<data>`) or JSON payloads to isolate raw data
→
3. LLM Attention & Inference
Attention heads lock onto Markdown headers & JSON keys
→
4. Structured Output
Parseable JSON or rich Markdown rendered in UI / APIs

1. Markdown Context Layer

Best for: Prompt architecture, step-by-step reasoning chains, human-facing docs, tables, and system roles.

⚡ Token-efficient syntax (`#`, `-`, `|`) that models are extensively pre-trained to recognize.

2. JSON Schema Layer

Best for: Machine-to-machine integrations, function/tool calling, database records, and deterministic API contracts.

🔒 Strict schema validation (OpenAI JSON Mode, Gemini Structured Outputs, Anthropic Tools).

3. XML Tag Delimiters

Best for: Isolating untrusted user input, raw notes, transcripts, or code snippets from system instructions.

🛡️ Prevents prompt injection and eliminates instruction-data boundary confusion.

📝 Markdown in LLM Inputs & Outputs

Markdown Focus

Markdown is the native language of Large Language Models. Models are trained on petabytes of GitHub repositories, technical documentation, and Wikipedia articles. Using Markdown headers establishes strict semantic hierarchies.

1. Markdown as Context Input (The 3 Cs)

Structuring prompt inputs with Markdown headers (### ROLE, ### TASK, ### CONSTRAINTS) signals distinct semantic compartments to LLM attention heads:

Markdown Input Prompt Example 
### SYSTEM / ROLE
You are an expert Technical Writer analyzing API specifications.

### OBJECTIVE
Summarize the authentication flow and rate limits for frontend engineers.

### CONTEXT & RULES
- Target Audience: Junior Web Developers
- Tone: Precise, instructive, minimal jargon
- Highlight edge cases in bullet points

### INPUT DATA
<api_spec>
Endpoint: POST /api/v1/auth/token
Rate Limit: 100 requests per minute per IP
Tokens expire after 3600 seconds.
</api_spec>

2. Markdown as LLM Output

LLMs generate Markdown for instant UI rendering, formatted tables, code blocks with syntax highlighting, and checklists:

Generated LLM Output (Rendered) 
## Authentication Overview

All client requests must authenticate via the token endpoint before accessing protected resources.

| Parameter | Value | Details |
| :--- | :--- | :--- |
| **Endpoint** | `POST /api/v1/auth/token` | Returns JWT Bearer token |
| **Rate Limit** | `100 req/min/IP` | Exceeding returns `429 Too Many Requests` |
| **TTL** | `3600s (1 hour)` | Refresh required before expiry |

### Key Edge Cases to Handle:
- ⚠️ Token expiration triggers automatic re-auth flow
- 🚫 IP rate limiting applies across all user accounts on the same proxy

💡 Why Markdown Works Best for Prompt Engineering

  • Token Efficiency: A header like ### ROLE consumes only 2-3 tokens, compared to verbose XML or nested JSON wrappers.
  • Pre-training Familiarity: High density in training datasets means models reliably adhere to heading boundaries.
  • Human Readability: Prompts are easy for developer teams to review, version control in Git, and debug.

📦 JSON in LLM Contexts & Structured Outputs

JSON & Schemas

While Markdown is ideal for human reading and prompt structure, JSON is the industry standard for programmatic data exchange and tool execution. Modern LLMs support strict JSON Schema decoding.

1. JSON as Input (Few-Shot & Data Payloads)

Passing structured JSON arrays for Few-Shot demonstrations primes the model to recognize exact key structures:

Few-Shot Prompt with JSON 
### TASK
Extract incident severity and affected microservices.

### FEW-SHOT EXAMPLES
[
  {
    "input": "Database replica in us-east went down, latency rose to 4s on checkout.",
    "output": {
      "severity": "CRITICAL",
      "service": "checkout-service",
      "region": "us-east"
    }
  }
]

### TARGET INPUT
<alert>
Search cache miss rate increased to 80% after deploy in eu-west.
</alert>

2. JSON as Structured Output (Deterministic Schema)

By specifying a strict schema constraint, LLMs guarantee type-safe deserialization directly into code objects:

⚙️ How Constrained Decoding / JSON Mode Works in LLM Engines

During token generation, modern inference engines (e.g. OpenAI Structured Outputs, Gemini Schema) dynamically mask out tokens in the probability distribution that would violate valid JSON grammar or the specified JSON Schema, guaranteeing 100% syntactically valid outputs.

⚖️ Format Decision Matrix: Markdown vs. JSON vs. XML

Architectural Guide

Choosing the right format for inputs and outputs depends on whether the consumer is a human or an automated software pipeline.

Evaluation Dimension Markdown (###, -, |) JSON ({}, []) XML Delimiters (<tag>)
Primary LLM Role System Prompt Structure & Human Output Deterministic Machine Outputs & Payloads Untrusted Data Boundary Isolation
Token Overhead Lowest (Minimal syntax chars) Medium (Key repetition, quotes, braces) Low-Medium (Opening & closing tags)
Machine Parseability Requires Regex / Markdown Parser Direct (Standard `JSON.parse()`) Requires XML/DOM Parser
Prompt Injection Defense Moderate High (when escaped) Highest (Explicit boundary isolation)
Streaming UI UX Best (Progressive Markdown rendering) Requires partial JSON stream parsers Awkward for direct user display
Recommended Use Case Role definitions, task briefs, report outputs API payloads, function calling, DB insertion Encapsulating raw customer emails, articles

🏆 The Production "Golden Standard" Hybrid Prompt Formula

Production LLM systems combine all three formats into an optimal hybrid architecture:

Recommended Production Prompt Architecture 
### ROLE & PERSONA [Markdown]
Senior Customer Intelligence Lead.

### INSTRUCTIONS [Markdown]
Extract sentiment, key issues, and churn risk from customer feedback.

### INPUT DATA [XML Tag Boundary]
<customer_feedback>
I have been waiting 3 weeks for my shipment. Your support team ignored my last 2 emails.
</customer_feedback>

### OUTPUT FORMAT & CONSTRAINTS [JSON Schema]
Return ONLY a valid JSON object matching this schema:
{
  "sentiment": "POSITIVE" | "NEUTRAL" | "NEGATIVE",
  "urgency": "LOW" | "MEDIUM" | "HIGH",
  "key_issues": string[],
  "churn_risk": boolean,
  "recommended_action": string
}

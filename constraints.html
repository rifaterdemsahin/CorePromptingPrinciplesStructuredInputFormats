Input & Output Constraints in LLM Engineering

Explore how setting strict input boundaries (delimiters, length bounds, data schemas) and output constraints (JSON Schemas, Enums, missing-field null handling, anti-preamble rules) transforms chaotic LLM inference into production-grade determinism.

📥 1. Core Input Constraints

  • Boundary Delimiters (<input_data>): Prevents user-provided inputs from escaping their intended context and masquerading as system commands (Prompt Injection Defense).
  • Persona & Role Scope (### ROLE): Constrains the model's vocabulary, reasoning horizon, and confidence calibration.
  • Input Length & Format Whitelists: Reject or truncate malformed input before token processing.

📤 2. Core Output Constraints

  • Strict JSON Schema: Restricts valid outputs to precise typed fields (strings, numbers, arrays, booleans) compatible with JSON.parse().
  • Missing Data Fallback (null Rule): Instructs the model explicitly to return null rather than inventing dates, prices, or names.
  • Enum Whitelisting: Limits categorical classifications to predefined constants (e.g. "PENDING" | "SHIPPED" | "REFUNDED").
  • Negative Prompt Rules: "Do not include conversational preamble or markdown code fences."
